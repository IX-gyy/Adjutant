# 记忆系统测试用例

> **测试前提**：确保 GLM API Key 已配置，模型全部加载完成 (状态栏四个指示灯常亮)，设置面板中"长期记忆管理"区域可见。

---

## 一、结构化记忆提取（类型标签）

### TC-1.1 属性记忆提取

**操作**：输入以下消息，等待 AI 回复，然后继续发 2 条消息触发自动提取（或发一条带"一定要记住"的消息强制触发）：

```
我叫张三，今年28岁，在北京的一家科技公司做软件工程师
```

**预期结果**：
1. 打开设置 → 长期记忆管理 → 查看所有记忆
2. 能看到一条记忆，内容类似"指挥官叫张三，28岁，在北京科技公司做软件工程师"
3. **类型标签显示为"属性"**（橙色标签）

**验证点**：类型标签 = `属性`，importance >= 5

---

### TC-1.2 偏好记忆提取

**操作**：
```
我很喜欢喝咖啡，尤其是冰美式，但讨厌喝奶茶
```

**预期结果**：
1. 记忆列表中新增记忆
2. 类型标签显示为**"偏好"**
3. 内容包含"喜欢喝冰美式"和"讨厌奶茶"

**验证点**：类型标签 = `偏好`

---

### TC-1.3 计划记忆提取

**操作**：
```
下周五我要去上海出差，要记得提前订机票
```

**预期结果**：
1. 记忆列表中多了一条类型为**"计划"**的记忆
2. 内容包含"去上海出差"的信息

**验证点**：类型标签 = `计划`，TODO 系统也应捕获到"订机票"（属于 MCP 工具链正常行为，非记忆系统范畴）

---

### TC-1.4 事件记忆提取

**操作**：
```
昨天我参加了一个很重要的技术分享会，学到了不少关于AI的新东西
```

**预期结果**：
1. 记忆列表中多了一条类型为**"事件"**的记忆
2. 内容包含"技术分享会"

**验证点**：类型标签 = `事件`

---

### TC-1.5 习惯记忆提取

**操作**：
```
我每天早上7点起床跑步，这个习惯已经坚持三年了
```

**预期结果**：
记忆列表中出现类型为**"习惯"**的记忆，内容包含"每天早上7点起床跑步"

**验证点**：类型标签 = `习惯`

---

### TC-1.6 不重要信息过滤

**操作**：
```
你好啊副官
```

**预期结果**：
1. 上述寒暄语**不会**触发记忆提取
2. 记忆列表中不会多出"你好"相关的记忆

**验证点**：importance < 3 的寒暄不被存储

---

### TC-1.7 三轮批量提取（修复验证）

> ⚠️ **此用例验证记忆提取丢失问题的修复**：旧版本每 3 轮只提取最后一轮，导致前两轮信息丢失。

**操作**：
1. 清空对话历史（点击垃圾桶）
2. 清空所有长期记忆（设置 → 删除所有长期记忆）
3. 连续输入以下三条消息（每条等待 AI 回复后再发下一条）：
   ```
   我叫李华，今年22岁，是北京大学计算机系的学生    ← 属性
   ```
   ```
   我特别喜欢喝冰美式咖啡，每天都要喝两杯         ← 偏好
   ```
   ```
   上周我参加了学校的编程比赛，拿了二等奖           ← 事件
   ```
4. 等待 10-15 秒（让后台提取线程处理）
5. 打开设置 → 长期记忆管理 → 查看所有记忆

**预期结果**：
1. 记忆列表中**同时存在**三条记忆：属性（李华/北大）、偏好（冰美式）、事件（编程比赛）
2. 类型标签分别为"属性"、"偏好"、"事件"
3. 不是只有最后一条（编程比赛）

**验证点**：GLM 收到了完整 3 轮对话，提取了全部有效信息

---

### TC-1.8 批量提取中寒暄被过滤

**操作**：
1. 清空记忆后，连续输入：
   ```
   我叫王五
   ```
   ```
   你好啊副官，今天天气不错
   ```
   ```
   我喜欢吃火锅
   ```
2. 等待提取完成后查看记忆

**预期结果**：
1. 记忆中有"王五"（属性）和"吃火锅"（偏好）
2. 记忆列表中**没有**"天气不错"或"你好"相关条目

**验证点**：寒暄在批量上下文中仍被 GLM 正确过滤

## 二、相关性门控召回

### TC-2.1 语义相关 — 高分召回

**操作**：
1. 先建立记忆："我养了一只叫大黄的金毛犬"
2. 等待记忆提取完成
3. 新开对话，输入：
```
我家的狗最近胃口不好怎么办
```

**预期结果**：
1. AI 的回复中**提到了"大黄"或"金毛"**相关的内容
2. 查看 stderr 日志（如果有），能看到 retrieval 的 score >= 0.6

**验证点**：高相关度的记忆被正确召回并注入 prompt

---

### TC-2.2 语义无关 — 低分过滤

**操作**：
1. 确保已有多条关于个人信息/偏好的记忆
2. 输入与所有记忆完全无关的问题：
```
1+1等于几
```

**预期结果**：
1. AI 应该触发"帝国数据库"兜底回复（因为 4B 模型无法回答计算问题）
2. 不应生硬地提到指挥官的偏好或事件

**验证点**：irrelevant query 不会导致记忆注入干扰

---

### TC-2.3 时间衰减验证

**操作**（需要修改系统时间，可选做）：
1. 确认有一条创建时间超过 30 天的记忆
2. 输入与该记忆语义相关的问题

**预期结果**：
- 超过 30 天的记忆由于 `recency_score = 0`，即使语义匹配也不会被召回

**验证点**：30 天时间窗口 + 时间衰减有效

---

### TC-2.4 加权排序验证

**操作**：
1. 确保有多条不同类型/重要性的记忆同时匹配一个查询
2. 查看后端日志中的 score

**预期结果**：
- 综合评分更高的记忆排在前面
- 高重要性 + 高语义匹配的记忆优先注入

**验证点**：`score = 0.5 × semantic + 0.25 × recency + 0.25 × importance`

---

## 三、对话摘要在 prompt 中的注入

### TC-3.1 结构化类别注入

**操作**：
1. 累积有属性、偏好、事件、计划四类记忆
2. 发送一条个人相关问题，如：
```
你觉得我最近状态怎么样
```

**预期结果**：
1. AI 回复中能分别引用不同类型的记忆
2. 检查 stderr 日志，prompt 中应出现结构化的分类标题：
   - `【关于指挥官的已知信息】`（属性和事实）
   - `【指挥官的偏好】`（偏好）
   - `【指挥官近期的关键事件】`（事件）
   - `【指挥官的计划安排】`（计划）

**验证点**：四类记忆分组注入，而非混在一起

## 四、清除对话 vs 删除记忆（分离测试）

### TC-4.1 清除对话不影响长期记忆

**操作**：
1. 先确认记忆列表中有 N 条记忆（记住数量）
2. 点击状态栏的**垃圾桶按钮** → 确认"清除当前对话"
3. 打开设置 → 长期记忆管理

**预期结果**：
1. 对话历史被清空（页面消息消失）
2. 记忆列表中的记忆**完整保留**，数量仍为 N
3. 弹窗文案明确说明"不会删除 AI 对您的长期记忆"

**验证点**：`clear_history` 只清 `chat_history` + `history.json`，不碰 ChromaDB

---

### TC-4.2 删除单条记忆

**操作**：
1. 打开设置 → 长期记忆管理 → 查看所有记忆
2. 点击某条记忆右侧的**垃圾桶图标**
3. 在确认弹窗中点击"删除"

**预期结果**：
1. 该记忆从列表中**立即消失**
2. 记忆计数 **-1**
3. 关闭设置面板再重新打开，该记忆**仍然不存在**（持久化删除）

**验证点**：ChromaDB 中对应 `mem_id` 的文档已删除

---

### TC-4.3 清空所有记忆（危险操作）

**操作**：
1. 打开设置 → 长期记忆管理
2. 点击红色"删除所有长期记忆"按钮
3. 第一个确认弹窗 → 点击"全部删除"
4. 再发送一条与旧记忆相关的消息：
   ```
   你还记得我叫什么名字吗
   ```

**预期结果**：
1. 确认后显示成功通知："已删除 N 条长期记忆"
2. 记忆列表显示"暂无长期记忆"
3. 记忆计数显示 "0 条"
4. 再次对话时，AI **不再**引用之前提取的记忆，会回答"不知道"

**验证点**：`clear_all_memories` 完全清空 ChromaDB collection

---

### TC-4.3b 清空后对话历史不受影响

**操作**：
1. 在有对话历史的情况下执行 TC-4.3
2. 观察对话页面

**预期结果**：
- 当前对话页面上的消息**不受影响**，仍然可见
- （如果当前对话被清空了说明误触了清除历史按钮，非本用例）

**验证点**：删除记忆 ≠ 清除对话

## 八、记忆去重

### TC-8.1 重复信息不重复存储

**操作**：
1. 输入："我叫张三，今年28岁"
2. 等待提取完成后查看记忆（应该有 1 条）
3. 再次输入几乎相同的内容："对了，我再说一次，我叫张三，今年28岁"

**预期结果**：
- 记忆列表中**不会**出现两条相同的"张三"记忆
- stderr 日志中能看到 `_is_similar()` 的相似度判断（ratio > 0.8 被跳过）

**验证点**：基于 `difflib.SequenceMatcher` 的相似度去重生效

## 九、边界条件

### TC-9.1 记忆为空时的表现

**操作**：
1. 清空所有记忆（TC-4.3）
2. 发送对话消息：
```
你还记得我的名字吗
```

**预期结果**：
1. AI 回复中**不含**任何错误的记忆引用
2. 不会抛出异常或报错
3. 设置面板显示"暂无长期记忆"

**验证点**：`retrieve_relevant()` 在 collection 为空时返回 `[]`

---

### TC-9.2 API Key 未配置时

**操作**：
1. 清空设置中的 GLM API Key
2. 发送包含个人信息的消息
3. 查看记忆管理区域

**预期结果**：
- 记忆系统不崩溃，不影响正常聊天功能
- 不会尝试提取记忆（`memory_manager.enabled = False`）
- stderr 显示"未设置 ZHIPU_API_KEY，长期记忆提取功能不可用"

**验证点**：优雅降级，不影响核心对话功能

---

### TC-9.3 单条记忆删除不存在的 ID

**操作**：
- 通过代码/控制台发送一个不存在的 `mem_id` 删除请求

**预期结果**：
- 不会崩溃
- 后端返回错误 `"记忆删除失败"`

---

### TC-9.4 未到提取轮次就关闭——重启恢复

> ⚠️ **验证 Fix 2（持久化）**：用户说了个人信息但还没轮到提取就关闭应用，重启后不应丢失。

**操作**：
1. 清空所有记忆和对话
2. 输入一条含个人信息的消息：
   ```
   我叫赵六，今年30岁，是一名医生
   ```
3. 再输入一条：
   ```
   我养了一只猫叫小花
   ```
4. **直接关闭应用**（不要等到第3轮触发提取！）
5. 重新启动应用
6. 输入第3条消息（触发提取）：
   ```
   我喜欢周末去爬山
   ```
7. 等待 10-15 秒
8. 打开设置 → 查看记忆

**预期结果**：
1. 记忆列表中**同时存在**三条信息：赵六/医生、猫/小花、爬山
2. 关闭前的两条信息没有丢失
3. stderr 日志可见 `[Backend] 已恢复 2 轮未提取对话`

**验证点**：`pending_extraction.json` 持久化和恢复生效

---

### TC-9.5 清除对话时同步清除未提取缓存

**操作**：
1. 输入 1-2 条含个人信息的消息（不触发提取）
2. 点击垃圾桶 → 清除当前对话
3. 检查 `%APPDATA%/ArtanisAI/pending_extraction.json` 文件

**预期结果**：
- 文件已被删除（或内容为空数组 `[]`）
- 再次正常对话时不会把已清除的旧对话提取为记忆

**验证点**：清除对话和清除未提取缓存的行为一致
